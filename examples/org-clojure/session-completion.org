* Intent

A session's completion is an interpretation of recorded temporal facts. Completion is not an independently asserted mutable status.

* Vocabulary and authority

- =:session/started-at= is an authoritative observation that the session began.
- =:session/ended-at= is an authoritative observation that the session ended.
- =completed?= is a derived interpretation.
- =:session/status= is not authoritative and must not influence completion.

* Normative claims

** claim/session-completion-derived-from-end

A session is complete if and only if an end observation exists in the applicable fact basis.

** claim/session-status-not-authoritative

Adding, removing, or changing an unrelated =:session/status= value cannot change the result of =completed?=.

* Examples

| started-at | ended-at | derived completed? |
|------------+----------+--------------------|
| t1         | absent   | false              |
| t1         | t2       | true               |

* Falsification targets

The verifier should attempt to find:

- a basis with =:session/ended-at= where =completed?= is false;
- a basis without =:session/ended-at= where =completed?= is true;
- an unrelated fact that changes completion;
- a =:session/status= value that changes completion;
- a test that remains green when =completed?= is replaced with a constant.

* Experiment validity

The project should demonstrate that the property fails when:

1. =completed?= always returns =true=;
2. =completed?= always returns =false=;
3. =completed?= reads =:session/status= instead of =:session/ended-at=.

The committed evidence should record variant counts and survivors rather than merely asserting that mutation testing was performed.

* Current scoped judgment

The evidence supports =:not-falsified-within-scope= for the two claims above.

It does not establish behaviour for concurrent writers, clock skew, or malformed temporal facts.
